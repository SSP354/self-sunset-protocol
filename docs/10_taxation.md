# 10_徴収 — 取引時点での確定と、生涯の記録

## 適用範囲

この版は「接続が普遍的に存在する」ことを前提に書かれている。
SSPは特定の接続技術に依存しない。ネットもAIも、現時点で利用可能な接続と
補助の形式にすぎず、新しい接続方法が現れるたびにこの章は更新される。
前提が満たされない範囲は、欠落ではなく、この版の適用外として宣言する。

## 前提

税は、人が生涯にわたって払い続けるものである。
一方で、個々の税には寿命がある。寿命が来れば徴収の方法も更新される。

したがって二つの時間が併存する。
- 税の時間：短く、更新され、そのつど再決定される
- 記録の時間：長く、本人の一生と等しい

## 設計目標

計算は自動化する。金額は可視化する。記録は本人が持つ。

## 1. 自動化と可視化の分担

自動化するもの：税額の計算、送金、申告手続きそのもの。
自動化しないもの：いくら払ったかを本人が知ること。

取引が成立するたびに、支払側へ次を返す。

- 適用された税の一覧（税ID）
- それぞれの税率と金額
- それぞれの用途
- それぞれの失効予定日と、更新判断サイクルの開始時期

手続きの負担は消してよい。負担の感覚は消してはならない。

## 2. 二重の台帳

中央が集計する税額と、本人の手元で積み上がる税額は、常に一致するよう設計する。

- 本人は自分の徴収記録を、専門家を介さずに読める形で保持する
- 中央は集計と統計を保持する。個体の履歴は保持しない
- 両者の差分は、それ自体が信号として社会的神経系に入る（07 参照）

従来、正しい台帳は徴収側にあり、個人は反証する側に置かれてきた。
ここでは二つの台帳が対等であり、不一致は個人の疑義ではなく系の異常として扱われる。

## 3. 記録の寿命 — 人を超えない

- 個人の徴収記録は、本人の一生にわたって保持される
- 本人の死後、相続・清算に必要な手続きが完了した時点で消去される
- 消去後、集計統計にのみ痕跡が残る。個体の履歴は復元できない

順序を明示する。

  権限の寿命 ＜ 税の寿命 ＜ 記録の寿命 ≦ 人の一生

人の一生を超えて存続する記録を、SSPは持たない。

消去は不可逆であり、それ自体が強い権限である。よって消去を実行する役職にも
期限・手続き・確認の遅延を置く。死の確認から消去までの猶予は、遺族の請求権が
消えないだけの長さを取る。

## 4. 閲覧権限の寿命 — 記録より短い

記録が長く残ることの危険は、記録の存在ではなく、読める者の存在にある。

- 記録は本人の側に置く。本人以外の閲覧はすべて期限付きの権限として発行する
- 権限には、目的・範囲・期限・発行理由が付く。期限が来れば自動的に失効する
- 集計目的の参照は、個体を特定しない形でのみ行う
- 権限の発行履歴は、本人が常に見られる

## 5. 更新は、必ず届く

税の寿命が来るたびに、徴収方法は更新され、可視化され、通知される。
通知は「送った」ではなく「届いた」ところまでを設計に含める。

ただし到達保証は強い力である。無制限に使えば、注意そのものを消耗させ、
結果として更新の判断は無関心に流れる。

- 到達確認を要求する通知には、期間あたりの上限を置く
- 上限を使う対象は、寿命の到来・徴収方法の変更・本人負担額の変化に限る
- 到達を強制する権限は、その通知の種類ごとに期限付きで与えられる

## 6. 伴走する補助

税の管理は、専門家に委任するものではなく、本人が行えるものとして設計する。
その差を埋めるために補助（現時点ではAI）が伴走する。

条件を三つ置く。

- 補助は本人の側に立つ。徴収側の補助と本人側の補助を同一のものにしない
- 補助は答えではなく根拠を返す。検算できない補助は、自動化が消したはずの
  不可視性を作り直す
- 補助は複数の独立した実装が存在しうる。差分検出の機能を単一の提供者が
  独占しない

補助が使えない者が不利にならないよう、補助なしでも読める形式を記録の
既定とする。
