## なぜ Self Sunset Protocol を作るのか

私は、不特定多数の一人です。

社会を構成する一人であり、

地球全体を構成する一人でもあります。

Self Sunset Protocol は、

1人の視点から、より良い社会のあり方を考え、試し、学び続けるためのプロジェクトです。


## なぜ義務が鎖に見えるのか

まず、二つの義務を分けておく。

納税の義務には、罰則も強制力もある。
各税法には逋脱に対する罰則があり、
国税徴収法にもとづく滞納処分は、
裁判所の判決を経ずに財産を差し押さえることができる。
加算税と延滞税も課される。

勤労の義務には、直接の罰則はない。
ただし強制力がないわけではない。
生活保護は「能力に応じて勤労すること」を要件に含み、
雇用保険の基本手当は求職活動の実績を要件とする。
給付を止めるという形で、強制力は働いている。

したがって、ここで問題にするのは罰則の有無ではない。

働いていない人が後ろめたさを感じる理由は、
義務が強いからではない。
**貢献を示す経路が、一つに偏っているから**である。

貢献の記録経路そのものは、すでに複数ある。

厚生年金には育児期間の保険料免除と従前標準報酬のみなし措置があり、
雇用保険には育児休業給付と介護休業給付がある。
内閣府は家事・育児・介護・ボランティアを無償労働として貨幣評価し、
公式統計に載せている。

問題は、経路が無いことではない。

- 経路が制度ごとに分断されていること
- 本人が、自分の記録を一箇所で通覧できないこと
- 賃金労働の記録だけが、所得と年金と信用という複数の帰結に接続していること

この非対称のために、
記録されていても、本人には見えず、社会にも見えない。

見えないものは、無いことにされる。
無いことにされた側は、自分で自分を責める。

義務が鎖になるのは、
可視化経路が一本だけ社会的な帰結に接続しているときである。

Self Sunset Protocol が扱うのは、義務の撤廃ではない。
**経路を増やし、記録を本人の手元に戻すこと**である。

（記録を本人が持つという設計は `10_taxation.md` の二重の台帳へ、
可視化と監視が同じ操作であるという問題は `02_Questions.md` へ続く。）



## これは、村社会への回帰ではない。

村の共有については、しばしば
「出ていけなかったから成立した」と語られる。

しかしこれは、事実としては正確でない。

前近代の日本の村落でも、奉公や出稼ぎによる人の移動は相当の規模で起きていた。
人返し令が繰り返し出されたこと自体が、移動が現に起きていた証拠である。

共有資源の管理に関する研究（エリノア・オストロムら）も、
共有が成立する条件として挙げているのは、
境界の明確さ、当事者による規則形成、監視、段階的な制裁、
低コストの紛争解決、組織する権利の承認であって、
退出不可能性ではない。

退出できる状態での相互扶助にも、先行例がある。

- 無尽、頼母子講
- 十九世紀イギリスの友愛組合
- 協同組合運動
- 労働組合の共済、相互会社形態の保険

したがって、
「退出できる相互扶助は存在したことがない」という主張は成り立たない。

Self Sunset Protocol が未検証なのは、退出可能性そのものではない。

先行例はいずれも、
構成員の数が限られ、
成員資格の管理と評判の共有が可能な規模に依存していた。

**匿名のまま、大規模に、退出できる状態で、相互扶助を成立させること。**

未検証なのは、この組み合わせである。

だからこれは、復古ではない。
そして、まったくの新規でもない。
先行例の設計原理が、どこまで規模と匿名性に耐えるかを試す設計である。

段階的な制裁という原理が、
現在の Self Sunset Protocol にはほとんど実装されていない。
循環遮断という強い措置か、何もしないかの二択しか持っていない。
これは先行研究を参照して初めて見えた欠落である。
